1. Resumen del proyecto

AeroCol es una aplicación web hecha en React para buscar vuelos nacionales en Colombia, calcular el valor de una reserva según pasajeros y clase, y guardar los tiquetes emitidos.

  • Conecta 6 ciudades (BOG, MDE, CLO, BAQ, CTG, BGA) con 76 vuelos en 30 rutas directas.
  • Los datos de vuelos, ciudades, clases y reservas se consumen desde un servidor local en Node.js (server.cjs) conectado a db.json.
  • Si el servidor no está encendido, la app usa localStorage como respaldo para no perder las reservas.
  • Incluye cambio entre modo oscuro y modo claro guardado en el navegador.

2. Arquitectura, árbol de componentes y ubicación de estados

Los estados que comparten varios componentes viven en App.jsx (elevación del estado). Los datos bajan por props y los eventos suben mediante funciones callback. 

                                    App.jsx
      [origen, destino, orden, vueloSeleccionado, reservas, vuelos, ciudades, clases, darkMode]
                                       │
        ┌──────────────────┬───────────┴───────────────┬──────────────────┐
        │                  │                           │                  │
    <Header />     <SelectorRuta />             <ListaVuelos />    <MisReservas />
  (tema oscuro)            │                           │                  │
                     ┌─────┴─────┐              ┌──────┴──────┐     (onEliminar)
                     │           │              │             │
              <SelectCiudad> <SelectCiudad> <TarjetaVuelo> ×N  (estado vacío)
                 (origen)      (destino)    (onSeleccionar)
                                                  │
                                         <FormularioReserva />
                                     [Local: nombre, pasajeros, claseId]

Decisiones de estado

  • origen y destino en App.jsx: Los comparten SelectorRuta (para excluir la ciudad de origen en el selector de destino) y ListaVuelos (para filtrar los vuelos de la ruta).
  • Selección en ListaVuelos y TarjetaVuelo: ListaVuelos recibe vueloSeleccionado (para resaltar la tarjeta activa) y onSeleccionarVuelo (para notificar a App.jsx).
  • reservas en App.jsx: Es el ancestro común entre FormularioReserva (quien crea la reserva) y MisReservas (quien lista y elimina).

4. Funcionalidades (F1, F2, F3)

F1 - Formulario de reserva

Usa inputs controlados con value y onChange. El total no se guarda en un useState, sino que es un estado derivado calculado en cada render multiplicando precio, pasajeros y factor de clase. A TarjetaVuelo se le agregaron onSeleccionar y esSeleccionada.

F2 - Mis reservas y persistencia

Se respeta la inmutabilidad de React: no se usa .push() porque mutaría la referencia en memoria sin disparar un nuevo render. Para agregar se usa [...prev, nuevaReserva] y para eliminar prev.filter(r => r.id !== id). Sin almacenamiento persistente, al recargar la pestaña se perderían las reservas; por eso se sincronizan en App.jsx con el servidor y localStorage.

F3 - Ordenar y seleccionar

Como .sort() modifica el array original, primero se saca una copia con [...vuelosFiltrados]. El estado orden vive en App.jsx, así que se mantiene al cambiar las ciudades de ruta. Al seleccionar una tarjeta se resalta y se abre el formulario.

5. Servidor local y rutas API

El backend corre en http://localhost:3001 usando únicamente módulos nativos de Node.js (http, fs, path).

MétodoRutaDescripción
GET/api/ciudadesDevuelve las ciudades disponibles.
GET/api/clasesDevuelve las cabinas y sus multiplicadores de precio.
GET/api/vuelosDevuelve el catálogo completo de vuelos.
GET/api/reservasDevuelve las reservas almacenadas en db.json.
POST/api/reservasRegistra una reserva nueva en db.json.
DELETE/api/reservas/:idBorra una reserva según su id.

6. Cómo ejecutarlo

# 1. Instalar dependencias (solo la primera vez)
npm install

# 2. Terminal 1 - Iniciar el servidor de datos
npm run server

# 3. Terminal 2 - Iniciar React con Vite
npm run dev

Luego abrir http://localhost:5173 en el navegador. En Windows también se puede ejecutar iniciar.bat.
