01 / Evolución del Sistema

De buscador estático a plataforma completa

Versión inicial

  • Filtro básico por ciudad de origen y destino.
  • Datos estáticos dentro del código fuente.
  • Sin selección de vuelos ni gestión de reservas.

Plataforma actual

  • 6 ciudades y 76 vuelos servidos desde server.cjs.
  • Flujo completo: buscar, ordenar, elegir, reservar y cancelar.
  • Respaldo automático en localStorage y modo oscuro/claro.

03 / Funcionalidad F1

Formulario controlado y estado derivado

Estados locales en FormularioReserva

nombre, pasajeros y claseId viven dentro del formulario porque ningún otro componente necesita leerlos mientras el usuario llena los campos.

Por qué el total no es un useState

Es un dato derivado: se calcula directo en cada render multiplicando precio, pasajeros y factor. Guardarlo aparte podría causar desincronización.

Vuelo AC-006 ($260.000) × 2 pasajeros × Ejecutiva (1.6) = $ 832.000 COP
04 / Funcionalidad F3

Ordenamiento y selección en catálogo

Ordenar sobre una copia

Como .sort() modifica el array original, hacemos primero una copia con spread operator:

const vuelosOrdenados = [...vuelosFiltrados].sort((a, b) => {
  if (orden === 'precio-asc') return a.precio - b.precio;
  if (orden === 'hora') return a.hora.localeCompare(b.hora);
  if (orden === 'avion') return a.avion.localeCompare(b.avion);
});

Comportamiento

  • El criterio de orden vive en App.jsx, así que se mantiene al cambiar de ruta.
  • TarjetaVuelo recibe esSeleccionada para resaltarse y onSeleccionar para abrir el formulario.
